C4 / containers

Container architecture

Synthetic feature values cross the risk-service boundary as ciphertexts; the service returns an encrypted score. Public protocol metadata remains visible.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

This predicts the CDC reported prediabetes/diabetes label for screening. It does not predict future onset or mortality, and it is not a diagnosis.

  1. The operator uses the browser. Public HTTPS leads to Netlify; the SSH tunnel leads to Hospital. Netlify has no Hospital API connection.
  2. Hospital sends 19 ciphertexts and a public key to the risk service. The service returns Enc(z); only Hospital decrypts.
  3. Hospital writes AES-GCM payloads to its vault. The service loads public model weights. Both containers share a trusted-admin host.

Infrastructure

Deployment topology

The approved MVP uses two containers on one VM. A second host is optional; the VM administrator remains trusted.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

No edge connects Netlify to the hospital. Actual final English LinuxONE execution, provider identity and measurements still require original evidence.

  1. The operator tunnels to VM loopback port 8080. Hospital and service communicate on the Docker network using mutual TLS 1.3 at port 8443.
  2. The vault volume stores ciphertext envelopes. The external AES key is mounted only into Hospital. External TLS files are scoped per container.
  3. The Paillier private key is generated in Hospital memory. Netlify is separate; final Community Cloud execution evidence is not established by a topology drawing.

Flowchart

Hospital flow

The hospital owns plaintext validation, encryption, decryption, interpretation and encrypted storage. The browser is inside its trusted demo workflow.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

The Hospital API is reached through SSH in the team demo. The static public site does not accept patient evaluations.

  1. Read the synthetic evaluation, select its input and validate the 19 integer feature codes. Invalid input returns HTTP 400.
  2. Encrypt the features, call the authenticated risk service and validate/decrypt its response. Transport or response-protocol errors return HTTP 502.
  3. Apply sigmoid and the validation threshold. Save the encrypted synthetic evaluation in the vault before returning risk, factors and timings.

Flowchart

Risk-service flow

The service holds the public model and its TLS identity. It receives encrypted input values and returns an encrypted linear score.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

Encrypted values hide feature contents from the service; public keys, identifiers, message sizes, model metadata and timing remain visible. Audit checks are scoped observations, not proof against a malicious host administrator.

  1. TLS client authentication precedes HTTP handling. HTTP checks reject unsupported routes, sizes and content types; protocol/model validation rejects invalid messages.
  2. Validate public-key and ciphertext groups plus overflow bounds, then compute and re-randomize Enc(B + sum(W[i] * x[i])). No private Paillier key is held.
  3. If audit mode is enabled, capture the exact wire bytes and metadata before HTTP 200. Evidence-storage failure returns HTTP 503; otherwise return Enc(z).

UML / sequence

Request sequence

Paillier protects the linear score. The sigmoid and threshold are applied only after hospital decryption.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

Exact encrypted/fixed-point agreement does not imply zero floating-point quantization error. The schema-wide logit error bound is approximately 1.03 × 10^-7. CKKS and Granite are not integrated.

  1. Browser sends a synthetic evaluation to Hospital. Hospital validates the integers and encrypts each feature.
  2. Hospital sends the ciphertext request to the service over mutual TLS 1.3. The service computes Enc(z) and completes optional audit capture before responding.
  3. Hospital decrypts z, divides by 10^9 and applies sigmoid/threshold. It stores an AES-GCM result and receives append/flush/fsync completion.
  4. Only then does Hospital return risk, contributions and timings to the browser. The service never receives the plaintext probability.

Record schema

Encrypted vault schema

The implemented operational store is an append-only JSONL file, not a relational database. Every saved evaluation has an encrypted payload.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

Envelope ID and nonce are visible on disk. The vault protects its payload; it does not encrypt all VM disks, logs, audit files or backups. No patient table, CURP, SQL engine, record-editing API or key-recovery system is implemented.

  1. The in-memory payload contains synthetic, profile, input, probability, risk_high and date.
  2. AES-256-GCM uses a separate external 32-byte key, a random 12-byte nonce and the request ID as associated data.
  3. The persistent JSONL envelope contains visible id and nonce plus ct (ciphertext with authentication tag). The dashed reverse relation is a decrypted view, not a foreign key.
  4. The Paillier private key is a different secret, kept in Hospital memory; it is not stored in the vault.

Logical ERD

Analytical data model

This is the implemented file-based analytical model. Relationships describe aggregation and lookup keys; no SQL foreign-key constraints or patient-level joins exist.

Read the notation subtitle: message, dependency and logical relationship lines have distinct meanings.SVG · editable vector
Read the diagram and implementation limits

One state has many state/year rows. Notifications use reporting geography, deaths residence and discharges treatment geography. Matching state/year does not mean the same people progress through a cascade. CDC and the hospital vault have no patient linkage to this mart.

  1. STATE CATALOG has logical key cve_ent. It relates one-to-many to STATE_YEAR_MART on state code and one-to-one to STATE GEOMETRY.
  2. The mart has logical composite key (cve_ent, anio), 256 rows: 32 states across eight years. Selected columns show population, notifications, deaths, discharges, treatment and a derived rate.
  3. Independent official sources are aggregated by state/year into the mart; its English presentation export supplies the public map, which looks up state geometry.
  4. These are file relationships, not SQL constraints or a linked patient cohort. CDC, ENSANUT and Hospital vault records are not person-joined to the mart.

Model lifecycle

Training uses public CDC survey records. ENSANUT is a separate exploratory reduced model; it does not validate the 19-feature demo clinically.

The separate ten-feature ENSANUT experiment shows transfer limitations and underestimated risk. Synthetic demo inputs have no clinical labels; do not assign them an AUC.

  1. Split the public CDC survey into stratified 70/15/15 subsets with seed 2026.
  2. Fit scaling and logistic regression only on training. Use validation to choose the threshold; freeze the model/threshold before test evaluation.

Data-flow DAG

Forecast pipeline

The optional forecast operates on aggregated notified cases. It is independent of the Paillier screening flow and uses no patient identifiers.

Demo ready; not a calibrated planning guarantee. No project unit cost is established. E5 is not encrypted; CKKS, Prophet, SARIMA and LinuxONE forecast training remain outside the delivered demo.

  1. Read 222 aggregate weekly series and reject missing/non-finite or nonweekly calendars.

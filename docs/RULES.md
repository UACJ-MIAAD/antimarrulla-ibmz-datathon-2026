# Operational rules

Summary of the Participant Guidebook and recorded event instructions. Official rules take precedence; see [LINKS.md](LINKS.md). This document is not an organizer waiver.

## 1. Build within the permitted event window

No continuation projects. Create the project code during the event; do not submit a previous personal/commercial project as the new solution. The exact virtual-Americas coding start remains an organizer question in [TIMELINE.md](TIMELINE.md). The portal opening is a separate fact.

| Preparation described as permissible | Work the guide reserves for the event |
|--------------------------------------|---------------------------------------|
| Research the problem and explore datasets | Write project code |
| Prepare the abstract and architecture plan | Bring a prebuilt prototype/notebook |
| Read IBM Z/LinuxONE documentation | Train the submitted model in advance |
| Prepare repository documentation | Build the final UI in advance |

Preserve actual history and disclose prepared data. Never backdate, rewrite published history or claim prerequisite order without evidence.

## 2. Required labs before building

Complete both organizer labs and save screenshots with actual dates:

1. *Predictive AI Hybrid AI scenarios (multi-model)*
2. *Predictive AI + Generative AI*

The guide describes these as prerequisites to the team's solution. The existing code/lab chronology remains disclosed; later completion does not retroactively change it.

## 3. Original work and attribution

Do not take other participants' code, projects or ideas. Open-source libraries/frameworks, public APIs and IBM tools are allowed subject to attribution and applicable terms. Include resource links in the submission and [README credits](../README.md#open-source-credits). Document dataset sources, transformations and source terms in [data/README.md](../data/README.md).

## 4. Generative AI transparency

The recorded event rules permit AI assistants with disclosure and team understanding of the code. Every member should be able to explain the submitted system. The team is deciding where to publish its separate declaration; a private draft is not completed disclosure. Record actual tools/tasks and human review without inventing a tool's identity or contribution.

## 5. Submission and language

Required: <=3-minute public video, public code link or accepted ZIP, required pitch PDF, exact title `Los Antimarrulla_IBM Z Datathon 2026 Project`, and open-source resource links. The video must show the problem, supporting data, solution, stack, LinuxONE instance and model. Follow [EVENT.md](EVENT.md) and [SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md).

The captain requires **English throughout all authored code, comments, UI, documentation and deliverables**. Preserve proper names, original source identifiers and historical evidence. This language instruction is attributed to the captain, not invented as an event rule.

## 6. Conduct

Keep the competition friendly. No harassment, hate, attacks on social groups or political advocacy. Respect race, nationality, religion, age, disability, appearance, gender identity, sexual orientation and programming experience. The recorded participation terms include SSF use of participant names/images/voices/recordings and sharing registered professional profiles with sponsors; participants should consult the actual terms. SSF may remove teams or members for rule violations.

## 7. Team and eligibility

Teams comprise four to six enrolled university students, undergraduate or postgraduate, from any major. Required technical setup was October 16. Verify registration and attendance records rather than infer completion from this plan.

## 8. Team rules

1. No sensitive real patient records in the repository; synthetic demo inputs only.
2. No credentials, keys or tokens, including Jupyter access tokens, in code or screenshots.
3. Ask for help after 30 minutes blocked; use the official IBM SME helpdesk for LinuxONE issues.
4. Respect the rest rota and leave an explicit handoff.
5. Another member reviews each release change; self-review and AI audit do not replace that review.
